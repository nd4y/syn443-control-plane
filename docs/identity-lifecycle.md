# Identity lifecycle and interrupted enrollment

The server accepting a request and the client receiving its response are different events. An enrollment can consume a device slot even if the phone loses the response, closes the browser, crashes or logs out. A client must not create a new key and silently abandon every earlier registration. It also must not retain logged-out private credentials merely to perform future cleanup.

## Owner-authenticated cleanup

`POST /v1/identity/devices/revoke` accepts a fresh pinned OIDC/DPoP identity, `requestId` and one to sixteen unique public-key thumbprints. The new proof key must match `cnf.jkt`; the nonce, method, URI, time, replay and exact raw-body hash checks remain required. The caller proves ownership through the issuer/subject pair, not a supplied owner ID, email, device ID or old key. A lost old key is not required.

The transaction locks that account, revokes only matching registrations owned by it, and retires their device sessions. Unknown and foreign thumbprints return the same204 response without revealing or changing foreign registrations. A denied/expired assignment may still clean up its own devices but cannot receive a session or configuration. Fresh-proof retries with the same request ID/body are idempotent for three minutes; changed bodies conflict. This endpoint is neither an enrollment grant nor an admin session.

Identity nonce challenges expire after three minutes. At most32 live challenge keys per account are admitted; expiration cleanup uses an index. This bounds retries that abandon a browser/key before completing enrollment. All paths share the same account lock with quota checks and device-session revocation. Runtime API privileges cannot approve/sign/revive a device.

## Android integration contract

The protocol core, Keystore adapter and bounded transport exist. The following coordinator/UI integration is still pending and must satisfy these rules before acceptance:

1. One controller owns a durable auth generation and single-use pending transaction. Persist a reserved key alias and public thumbprint before generating/using it. Browser state, nonce and PKCE verifier remain protected; no password is handled by the client.
2. Before sending enrollment, persist its request ID/body and mark its public thumbprint as potentially registered. A process restart retries the same request/key within the idempotency window or performs owner cleanup after fresh login. A timeout is not proof that no device was created.
3. Cancel/Logout invalidate the auth generation before later effects can commit, cancel the active raw socket and keep the bounded pool instance. No callback, queued DNS result, crypto completion or stale configuration may bypass that fence. Pre-existing thread interruption remains cancellation.
4. Logout stops VPN intent and retires the native owner, removes local sessions/assigned policy/private credentials, and attempts a proof-bound revoke when online. If the result is unknown or offline, keep only a bounded public-thumbprint tombstone. Do not claim server revocation. A subsequent fresh OIDC identity drains owned tombstones through the cleanup endpoint before trying a new enrollment, without retaining the logged-out signing key or token. Never silently revoke other devices to satisfy a quota.
5. Identity proof validation and policy activation are separate effects. A verified credential or immutable signed bundle may be cached only for its current auth generation; network observations and activation use the current VPN/network/config generations. Stop cannot become an automatic Connect. No network/key operation runs on the UI/Binder thread, and no unbounded pool is recreated on retry/logout.
6. For an existing local configuration, retain it encrypted on-device. An enrollment binding must be a separately verified delivery kind using pretrusted roots and a new device scope. Keep its policy journal separate from the earlier local-management ledger. Do not import an assigned profile into an unmanaged slot as an intermediate step: a crash there would bypass its signed lease. A bound-but-incomplete enrollment remains blocked until a valid candidate is present. A confirmed Logout may restore the preceding local mode only after Stop; ordinary fresh clients have no unsigned fallback.
7. Managed overlay identities/caches need explicit enrollment namespaces and cleanup after owner retirement. A synthetic direct-path pilot does not prove that NetBird/provider secret cleanup is complete. Do not advertise unsupported managed engine lifecycle capabilities.
8. Bootstrap roots and issuer/API origins come from a trusted operator/signed bootstrap, never an arbitrary API response. The pilot may use an operator-only debug staging file; release invitation/auth bootstrapping still needs its own acceptance. Deep-link handling is exact `syn443://oauth/callback`, state/issuer/nonce bound, single-use and boot/elapsed-deadline checked. Browser launch does not prove an interactive form/callback flow passed.

Required regression cases include a response lost after server commit, concurrent cancel and enrollment, cold restart before/after policy binding, reused callback/code, changed boot/clock, missing/invalidated key, stale crypto/DNS completion, cleanup with a new key, foreign thumbprints, disabled assignment, conflicting retry bodies, full challenge/worker queues, and logout while offline. Physical Wi-Fi evidence and real external-browser interaction remain separate from JVM/HTTP fixtures and from the excluded LTE/Doze/battery gates.

## Signed key and initial time binding

New enrollment publications use payload version2, required capability `policy.keybound.v2`, and a signed `keyThumbprint` alongside `targetDevice`. The publisher derives it from the independently authenticated immutable device key; owner templates cannot supply it. Clients call the bound verifier with a thumbprint computed from their own Keystore public key, not a delivery field. A valid signature for a delivery-selected device ID is insufficient. Version1 remains only for existing local-management fixtures/compatibility and is rejected by enrollment-bound verification. The locked schema, Go/Kotlin tests and public Go-issued signature fixture enforce this distinction. Do not activate a version1 policy through a new identity binding.

At first enrollment, the trusted-time floor also includes fresh issuer time from the verified HTTPS token response. A delivery-only clock cannot rewind below that independent identity time. Keep monotonic/boot anchors and bounded request-duration uncertainty; validity/lease checks use a conservative time bound while DPoP iat must remain within the server's accepted window. Persist these anchors with the binding and never extend a lease because the token/session was refreshed. The browser/coordinator integration must implement and test this; it is not implied by the current pure protocol tests.
