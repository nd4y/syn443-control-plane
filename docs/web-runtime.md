# Web runtime

The `web-runtime-image-linux-amd64` GitHub Actions artifact contains the separately deployable control console and support frontend. Both modes use the same `support-chat-web` executable as the verified control-plane release. The image contains the executable with embedded browser assets and the public CA bundle. Build-time credentials, providers, SQL connections and signing keys are outside the image. Control and chat actions use their configured versioned HTTP APIs and delegated browser identity.

Download the artifact for the intended commit, verify its GitHub digest, `SOURCE.txt` and `SHA256SUMS`, then load the image archive on the target container host. Use its exact revision tag as `SYN443_CHAT_WEB_IMAGE`. Configure `SYN443_INGRESS_CONTAINER` and `SYN443_CHAT_WEB_PRIVATE_DIR` in the deployment environment. The example in `deploy/support-chat-web/compose.yaml` leaves the listener on the existing gateway's loopback and publishes no ports. Each mounted file must be readable by UID 65532. Keep the JSON configuration and private TLS key owner-only. Browser and backend origin checks, PKCE, DPoP, and the API's access checks still apply.

The health check sends a bounded HEAD request to the configured listener with no credentials and requires its web-service header. For HTTPS it checks the configured certificate and name. Where the local gateway's TLS identity differs from the public origin, set `readinessServerName` to the name on the listener certificate. Readiness confirms the frontend completed initialization and can answer on its own listener. The login and backend API flows are verified separately.

The release job opens the embedded pages from the real container, verifies that the session endpoint rejects anonymous requests, then exercises support sign-in with Keycloak and a DPoP-bound API request. The console flow covers password login, fresh assurance and logout. The published acceptance report contains only the four required passing test names. The public Compose example starts the frontend independently. A pilot rollout and physical Android acceptance are separate release steps.
